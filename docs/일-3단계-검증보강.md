# 사실 검증·보강 프롬프트 (범용 — ⑤⑥)

**핵심 원칙**: 하나의 출처로 다 하지 않는다. **콘텐츠 성격에 따라 출처를 가른다.**

| 콘텐츠 성격 | 주력 출처 | 라벨 |
|---|---|---|
| 카피·서사·입지스토리·시장맥락·분위기 | **언론**(다수 교차확인) | 보강 |
| 일반 fact(명칭·규모·주체 등) | **공식 1차 문서 + 2단계가 받은 자료** | 검증 |
| 법정/핵심 수치(가격·일정·자격·비율·주체) | **1차 출처 문서(공고문·공시·사양서 등)** | 확정 |

> **왜**: 언론은 2차 출처라 보도자료 받아쓰기·반올림·오타가 매체 간 복제된다. 서사엔 최고지만 **숫자는 1차 문서로만 못박는다.** 2단계가 ③에서 받은 공식 문서 PDF가 있으면 **그게 1순위 정본**(언론은 보조).
> **이 단계 blocker**: G3-FACT · G3-EVIDENCE · G3-LEDGER · G3-FACTJSON 〔권고 1개는 진행을 막지 않는다〕
>
> **입력의 핵심 = OCR 이미지 텍스트**: 분양 원본은 콘텐츠가 이미지(CG)에 임베드돼 HTML `text.txt`는 면책 문구뿐인 경우가 많다. 따라서 **`ocr.json`(이미지 속 시설명·스펙·수치)이 HTML 텍스트보다 핵심 입력**이다. 둘을 합쳐 섹션별 fact를 도출하고 1차 출처로 검증한다. ⚠️ 2단계에서 인포그래픽 패널이 OCR 누락됐으면 3단계 전에 2단계 ④로 되돌아가 **전수 OCR부터 보강**(이미지 텍스트 없이는 정보 제약이 안 풀린다).
> **저장**: 섹션별 fact 검증 결과는 **산출물 `검증리포트.md`(extraction/)에 섹션별로** 기록하고, 확정 fact는 **`content.ts` 단일 소스**로. ⚠️ `docs/`나 페이지별 md에 현장 fact를 흩뿌리지 말 것(범용 docs·단일소스 원칙).

## 프롬프트 (복사해서 사용)

```
[입력]
- 2단계 산출물: <SAVE_PATH>/pages, ocr.json, docs(공식 PDF 포함), manifest.json
- 도메인: <DOMAIN_NOTE> (예: 분양) — 아래 ⑤ fact 목록·출처 사다리를 이 성격에 맞게 사용.

[작업]
- 2단계가 뽑은 핵심 fact를 공식 1차 출처와 1:1 대조(⑤)하고, 미확정/누락을 보강(⑥)한다.
- 산출물: factcheck.json, enriched.json, 검증리포트.md. 모든 항목에 source+sourceUrl+checkedAt 필수.

⑤ 외부자료 사실 대조 (도메인에 맞게 fact 목록·출처 교체)
- 핵심 fact를 공식 1차 출처와 1:1 대조. fact·출처는 대상 성격에 따라 정의한다.
  · 일반: 회사명/소재지/대표/연혁/제품 스펙/가격/연락처 → 공식 등기·공시·보도자료·제조사 사양서.
  · (분양 예시) 세대수·동수·층수·전용면적·대지위치·분양가·청약일정·자격·시행/시공/신탁 → 입주자모집공고문·청약홈·HUG·지자체 고시·건축물대장·토지이음·DART·언론.
- ★**2단계가 ③에서 받은 공식 문서 PDF가 있으면 그 PDF를 1차 출처로 우선 대조**(언론·2차 자료는 보조).
- 항목별 라벨: 일치 / 불일치 / 미확정 + 출처 + 확인일. factcheck.json.
- 불일치 시: 원문(사이트값) 보존(별도 필드), 더 강한 출처값을 병기, 어느 쪽이 맞는지 단정 금지(강한 출처 우선).

⑤-신뢰 (추측 차단 — 라벨 신뢰 강화, 타협 금지)
- **원문 발췌 의무**: 모든 `일치/불일치`는 URL만으로 불충분 — 출처 문서의 **실제 문장을 그대로 딴 발췌(quote) + 위치(sourceLocator: PDF p.N·표 이름·화면 캡션)**를 factcheck.json에 필수 기입. 발췌를 못 붙이면 그 항목은 **자동 status=미확정**(일치/불일치 라벨 금지). URL 한 줄은 위조가 쉬우나 원문 발췌+페이지는 사람이 즉시 대조 가능.
- **확인 방식 표기**: 각 항목에 `verifyMethod = 직접fetch열람 | 검색스니펫 | 추론`. **`추론`이거나 원문 fetch 실패면 무조건 status=미확정** — 그럴듯한 값을 지어 라벨 달지 말 것(이게 오차의 원인).
- **핵심 수치 사람 눈 대조**: 분양가·세대수·전용면적(평형)·청약일정·청약자격·시행/시공/신탁 3주체는 AI가 "공고문 몇 페이지/어느 표에 있다"까지만 짚고, **최종 확정 라벨은 사람이 그 페이지를 직접 보고** 확정. AI 단독 확정 금지 → reports/manual-evidence.json에 발췌+경로 첨부.
- **2패스 반박 검증**: 값을 채운 뒤, 2차로 **"이 값들이 전부 틀렸다고 가정하고 원문으로 반박하라"**를 1회 더 실행. 반박에서 원문 발췌로 방어 안 되는 항목은 미확정으로 강등.

⑥ 내용 보강
- 미확정·누락 항목을 외부 공식자료로 보강. 원문 보존(별도 필드), 출처+확인일 필수.
- 미공개·확정 전 정보 단정 금지 → "추후 안내". 전망성 항목은 "예정"+출처. enriched.json.
- 서사/카피용 보강(분위기·맥락)은 언론 다수 교차로 채우되, 수치는 ⑤의 1차 출처를 따른다.
- ★언론에서 가져온 항목은 ⑧ 보도 대장에 {매체, 보도일, 제목, 원문 URL, 인용한 fact, 귀속 페이지}로 남긴다 — 사이트 하단 ※ 주석·PRESS 카드(10단계)·보도 아카이브(13단계)가 이 표를 그대로 받아쓴다. ⚠️ 미러 게시판 페이지의 OG·메타는 대상 사이트 값이라 매체·보도일이 아니다 → 기사 본문에 적힌 매체명·보도일을 근거로 적고, 불명이면 "미상"(창작 금지).

⑦ 전사 대장 (이미지 fact → HTML 텍스트 귀속 계획) — thin content 방지 핵심
- ⑤⑥로 확정된 fact를 한 건도 빠짐없이 대장에 올린다. 특히 **ocr.json 이미지 임베드 값**: 타입별 면적표(전용·주거공용·공급·기타공용·계약·세대수), 사업개요 수치(대지·연면적·건폐율·용적률·특별공급 배분), 마감재 브랜드·모델, 특화시스템 항목, 시설/정원/광장명 등.
- 각 fact에 **처분 1개** 부여: `전사`(HTML 본문 텍스트로 넣음) / `병기`(큰 이미지 옆·아래 HTML 텍스트 동반) / `제외`(사유 명시 — 면책 문구·중복·비검색 필러 등).
  ★**기본값이 "이미지에만 있음"이 될 수 없다.** 이미지 안 글자는 검색·AI가 못 읽어 alt로도 불충분 → 반드시 전사/병기 중 하나이거나 **명시적 제외(사유)**. "이미지가 크니 텍스트는 얇아도 된다"는 판단 금지.
- 각 fact에 **귀속 페이지 1곳**(면적표=평면도 · 마감재/특화=프리미엄 · 사업개요 수치=단지 · 입지 수치=입지 · 핵심 스펙=메인 ABOUT). 같은 fact를 여러 페이지에 복붙 금지(near-duplicate 어뷰징). 실제 렌더 전사 여부는 11·16단계 게이트가 회귀 점검.
- 각 fact에 **출처(매체·날짜)와 ※ 표기 여부**를 함께 적는다. 1차 문서(공고문·건축물대장·지자체 고시 등)에서 온 확정 fact = **※ 불필요**(그냥 사실로 쓴다 — 시점 단서 "{공고일} 모집공고 기준"과 공고문 PDF 링크로 근거가 이미 선다. ⚠️ **공고문 PDF 링크까지 빼라는 뜻이 아니다** — 14단계 E-E-A-T 신호) · 언론에서 온 서사·호재·시장맥락 = **※ 필요** → 그 페이지 하단 ※ 주석으로 나간다. ⚠️ 본문 문장 안에 "보도에 따르면·알려졌다"류를 넣는 건 금지(6단계 §C 출처 자백). ※ 필요 fact는 ⑧ 보도 대장 행과 1:1.

[출처 사다리 — 분양(<DOMAIN_NOTE>=분양) 기준, 위일수록 강함]
★1 입주자모집공고문(PDF)  → 신탁사·건폐율·용적률·분양가·대지면적·정확 청약일정·계약조건 전부
★2 청약홈(applyhome) APT분양정보 → 세대수·공급금액·일정·자격(공고와 동일 법정값)
 3 HUG 분양보증/분양가 공시 → 분양보증·분양가 검증
 4 토지이음(eum.go.kr) 토지이용계획 → 대지위치·용도지역·면적
 5 지자체 고시(해당 시·군·구) → 사업계획승인·착공·건축개요
 6 DART/법인등기 → 시행 PFV·시공·신탁 주체
 7 언론 → 보조(상호 교차확인용)
(다른 도메인이면 이 사다리만 그 성격의 공식 1차 출처로 교체)

[기록 규칙 — 타협 금지]
- 항목별 라벨(일치/불일치/미확정) + source + sourceUrl + checkedAt(YYYY-MM-DD) 100%.
- 1차 출처 우선, 언론은 보조. 못 구한 항목은 "미확정 + 사유"로 정직하게(묵시적 생략 금지, 리포트에 명시).
- 사이트 표기 수치는 "{입주자모집공고일} 기준" 단서 + 광고심의필 + 시행/시공(/신탁) 3주체 푸터(분양광고 규정).
- 발췌 없는 라벨 금지: 일치/불일치는 원문 발췌(quote)+위치(sourceLocator)+verifyMethod 동반 필수. 추론·fetch실패=미확정(추측으로 라벨 달기 금지 — 오차 재발 방지). 핵심 수치는 사람 눈 대조 후 확정, 2패스 반박 1회 필수.

[한계 — 미리 고지]
- 웹검색이 지역 제한적이거나 공식 포털이 동적/인증이면, 공고문 PDF는 검색→직접 URL fetch로 시도. 안 뚫리면 "미확정 + 사유".
- 인증/회원 전용·미공개 자료는 진입 불가 → URL만 기록.

[출력 구조]
<SAVE_PATH>/

   · 전사 대장 표 컬럼: | fact | 값 | OCR 원본(이미지/패널) | 귀속 페이지 | 처분(전사|병기|제외) | 제외 사유 | 출처(매체·날짜) | ※ 표기(필요|불필요) |

[완료 조건 — 검증리포트.md에 보고]
⑤ 핵심 fact 전부 일치/불일치/미확정 라벨. 1차 출처 문서 확보 여부 명시. 불일치 목록.
⑥ 보강값 100% 출처+확인일, 원문 무변경. 미확정 항목은 "추후 안내" 사유 명시.
+ 신뢰 강화: 모든 일치/불일치에 원문 발췌(quote)+위치(sourceLocator)+verifyMethod 기입 · 추론/fetch실패=미확정 처리 · 핵심 수치(분양가·세대수·평형·청약일정·자격·3주체) 사람 눈 대조 · 2패스 반박 1회 수행 → reports/manual-evidence.json에 핵심 fact 발췌+경로 첨부.
+ 5단계(content.ts/site.ts)로 넘길 [확정 fact] 표 + [미확정→추후 안내] 목록.
+ factcheck.json · enriched.json · 검증리포트.md 3파일 모두 생성됨.
+ 이미지 속 텍스트(ocr.json) 전수 확보 확인 — 인포그래픽 패널 OCR 누락 0(누락 시 2단계 ④로 보강 후 재검증). 섹션별 fact는 검증리포트.md에, 확정 fact는 content.ts 단일소스에(docs/페이지별 md에 현장 fact 0).
+ ⑦ 전사 대장: 이미지 임베드 fact 100% 처분(전사|병기|제외+사유), 귀속 페이지 1곳 지정, 출처(매체·날짜)·※ 표기(필요|불필요) 기입, **"이미지에만 있음" 방치 0**. 요약이 아니라 실값 전사 계획.
+ ⑧ 보도 대장: 언론에서 인용한 fact 100%가 {매체·보도일·제목·원문 URL·인용 fact·귀속 페이지}로 기록됨. ⑦에서 "※ 필요"로 표시한 fact ↔ 보도 대장 행 1:1(누락 0). 매체·보도일 불명은 "미상" 명시(창작 0).```

## 참고 (블록 밖 — 사람용)

### 왜 a/b로 나눴나
- **2단계(추출)** 은 기계적·재현 가능(크롤·OCR) → 다음 현장에서 스크립트로 자동.
- **3단계(검증·보강)** 은 판단·출처 추적(1차 문서 대조) → 사람+AI가 매 현장 직접.
- 관심사 분리로, 추출 원자료는 그대로 두고 검증만 다시 돌릴 수 있다(원자료 재크롤 불필요).

### 흔한 함정
- **언론으로 숫자 확정**: 보도자료 복제 오류가 매체 간 전파됨. 면적·일정·가격은 1차 문서로만.
- **공고문 미확보로 미확정 방치**: 정규청약 종료 단지는 공고문이 공개·아카이브된 경우가 많다 → 검색→직접 fetch로 끝까지 시도.
- **미확정을 슬쩍 채움**: 창작 금지. "입주자모집공고 시점 기준 추후 안내"로 남기고 리포트에 사유.

### 산출물이 5단계의 입력
- `factcheck.json`·`enriched.json`·`검증리포트.md`가 5단계 `content.ts`/`site.ts` **단일 소스의 입력**이 된다.
- 페이지별 md로 흩뿌리지 않는다(중복·드리프트 방지) — fact의 집은 코드(content.ts/site.ts) 하나.

## ⑨ 키워드 리서치 — **3단계 직후 즉시 · AI가 자동 수행**

> ★ **실행 시점은 여기다(5단계 시작 전).** 5단계 URL·메뉴 라벨과 10~13단계 title·H1 정본이 이 결과로 확정되고, **title은 READ-ONLY**라 14단계에 가서 처음 하면 되돌릴 수 없다. [14단계 §키워드 리서치](일-14단계-SEO-GEO.md)는 여기서 만든 표를 **재검증·보강**하는 자리지 처음 만드는 자리가 아니다.
> **산출물**: `reports/keywords.json` · **게이트**: `G3-KEYWORD`(auto·blocker)

### 왜 자동으로 되나 — 네이버 자동완성이 근거

네이버 자동완성(`ac.search.naver.com`)은 **실제로 입력된 쿼리**만 노출한다. 즉 자동완성에 뜬 조합은 "이 현장에 대해 사람들이 실제로 치는 말"이라는 네이버 자체의 증거다. 추측 키워드를 배제한다는 이 단계의 목적은 이것으로 달성된다.

- ✅ 얻는 것 — 현장명에 실제로 붙는 조합어 전량(초성 스윕으로 자동완성 목록을 소진시킨다)
- ❌ 못 얻는 것 — **월간검색수 숫자**(공개 API 없음). 숫자가 꼭 필요하면 [네이버 검색광고 키워드도구](https://searchad.naver.com)를 사람이 병행한다(선택). **없어도 이 단계는 통과한다** — 순위(무엇이 더 많이 검색되나)는 자동완성 노출 순서가 대체한다.
- ⚠️ 자동완성이 **비어 있는 신규 현장이 정상**이다(분양 초기엔 현장명 검색량 자체가 없다). 그때는 `queries: []`로 기록하고 **지역·평형 축**(`{지역} 신축 아파트` 등)으로 폴백한다 — 게이트는 "조회를 수행했는가"를 보지 "몇 개 나왔는가"를 보지 않는다.

### 실행

① 아래 블록을 `scripts/keywords.mjs`로 저장 → ② `node scripts/keywords.mjs` → ③ `reports/keywords.json` 확인.
현장명은 `src/lib/site.ts`에서 자동으로 읽는다(하드코딩 0). 5단계 전이라 `site.ts`가 아직 없으면 인자로 준다: `node scripts/keywords.mjs "{현장명}"`.

```js
// scripts/keywords.mjs — 3단계 직후 키워드 리서치(자동)
// 네이버 자동완성 = 실입력 쿼리. 초성 스윕으로 목록을 소진시켜 현장명 롱테일을 전량 수집한다.
import fs from "node:fs";

const argName = process.argv[2];
const siteTs = (() => { try { return fs.readFileSync("src/lib/site.ts", "utf8"); } catch { return ""; } })();
const NAME = argName
  || (siteTs.match(/short:\s*["']([^"']+)["']/) || [])[1]
  || (siteTs.match(/name:\s*["']([^"']+)["']/) || [])[1];
if (!NAME) { console.error("현장명을 못 찾음 — 인자로 넘기거나 site.ts를 먼저 채울 것"); process.exit(1); }

// 초성 14 + 숫자 10 + 무접미 = 25회 조회로 자동완성 목록을 소진시킨다.
const SEEDS = ["", ..."ㄱㄴㄷㄹㅁㅂㅅㅇㅈㅊㅋㅌㅍㅎ".split(""), ..."0123456789".split("")];
const ORDER = new Map();          // 쿼리 → 최초 노출 순위(자동완성 상단일수록 수요 큼)
const ac = async (q) => {
  const u = "https://ac.search.naver.com/nx/ac?st=100&r_format=json&r_enc=UTF-8&q_enc=UTF-8&frm=nv&q=" + encodeURIComponent(q);
  const r = await fetch(u, { headers: { "User-Agent": "Mozilla/5.0" } });
  const j = await r.json();
  return (j.items || []).flat().map((it) => it[0]);
};
for (const s of SEEDS) {
  try {
    const hits = await ac(NAME + (s ? " " + s : ""));
    hits.forEach((h, i) => { if (!ORDER.has(h)) ORDER.set(h, ORDER.size + i); });
  } catch (e) { console.error("조회 실패:", s, e.message); }
}
const queries = [...ORDER.keys()].filter((k) => k.replace(/\s/g, "") !== NAME.replace(/\s/g, ""));

// 페이지 소유권 배정 — 한 키워드는 한 페이지만 소유한다(14단계 §키워드 소유권).
const BUCKETS = {
  sales:      ["분양가", "가격", "분양", "청약", "계약금", "중도금", "분담금"],
  modelhouse: ["모델하우스", "견본주택", "갤러리", "홍보관", "방문", "예약"],
  floorplan:  ["평면도", "평면", "타입", "㎡", "평", "구조"],
  location:   ["위치", "주소", "입지", "교통", "역", "학군"],
  complex:    ["단지", "세대", "동", "층수", "커뮤니티", "조경", "주차"],
  overview:   ["시행", "시공", "건설사", "입주", "준공", "일정", "사업"],
  news:       ["미분양", "잔여", "선착순", "후기", "소식"],
};
const assigned = {}; const unassigned = [];
for (const q of queries) {
  const tail = q.replace(NAME, "").replace(/\s+/g, " ").trim();
  const hit = Object.entries(BUCKETS).find(([, words]) => words.some((w) => tail.includes(w)));
  if (hit) (assigned[hit[0]] ||= []).push(q); else unassigned.push(q);
}

const out = {
  brand: NAME,
  collectedAt: new Date().toISOString().slice(0, 10),
  source: "naver-autocomplete(ac.search.naver.com) 초성 스윕 " + SEEDS.length + "회",
  note: "자동완성 노출 = 실입력 쿼리 증거. 월간검색수 숫자는 미포함(필요 시 검색광고 키워드도구 병행).",
  queries,                                  // 자동완성 순서 = 수요 순서 근사
  assigned,                                 // 페이지별 소유 키워드
  unassigned,                               // 어느 페이지도 안 가진 것 → 서브 본문 보강 후보(10~13단계)
  absent: Object.keys(BUCKETS).filter((p) => !assigned[p]),   // 자동완성에 안 뜬 축 = title 꼬리에 쓰지 말 것
};
fs.mkdirSync("reports", { recursive: true });
fs.writeFileSync("reports/keywords.json", JSON.stringify(out, null, 2), "utf8");
console.log(`[${NAME}] 자동완성 쿼리 ${queries.length}개`);
for (const [p, ks] of Object.entries(assigned)) console.log(`  ${p.padEnd(11)} ${ks.join(" · ")}`);
if (unassigned.length) console.log(`  (미배정 → 서브 본문 보강 후보) ${unassigned.join(" · ")}`);
if (out.absent.length) console.log(`  ⚠️ 자동완성 미노출 축: ${out.absent.join(" · ")} — title 꼬리·분양소식 주제로 쓰지 말 것`);
```

### 결과를 어디에 쓰나

| 산출 필드 | 소비 단계 | 쓰는 법 |
|---|---|---|
| `assigned` | **5단계** | 라우트 URL·메뉴 라벨을 그 검색어와 일치시킨다(예: `평면도`가 잡히면 메뉴·URL·H1·title·alt 전부 `평면도`) |
| `assigned` | **10~13단계** | 페이지별 TITLE·H1 정본의 꼬리 키워드. **소유 페이지 1곳만** 가진다 |
| `absent` | **10~13단계** | 자동완성에 안 뜬 축은 **title 꼬리에 넣지 않는다**(비검색 문구 = 자리 낭비) |
| `unassigned` | **10~13단계** | 서브가 안 가진 `{현장명}+X` = **해당 서브페이지 본문 보강** 소재. ⚠️ 분양소식 소재가 아니다 — `{현장명}+X` 롱테일 슬롯은 폐지됐다(15단계 §0) |

⚠️ **`queries`가 비었다고 title을 비워두지 말 것.** 현장명 자체는 언제나 주력 키워드다(직접 검색 유입). 자동완성은 **꼬리 키워드 선택**에만 쓴다.
