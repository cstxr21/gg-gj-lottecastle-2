## 공통 원칙 — 본문 밀도·이미지 활용 (thin 페이지 금지)

> ⚠️ **[필수 게이트] 이미지 전수 확인 → 분류표 → 완료조건 증명 (안 지키면 작업 무효 · 11·12·13단계 공통)**
> 1. **전수 확인 — 단, 이미 읽은 이미지를 세 번째로 다시 읽지 않는다**: 해당 카테고리 `public/images/<cat>/`의 이미지를 **한 장도 빠뜨리지 않고** 확인한다(추측·샘플링·파일명만으로 판단 금지). 확인의 **정본은 [2단계](일-2단계-정보추출.md) `ocr.json`(이미지 속 텍스트 전사)과 [4단계](일-4단계-이미지큐레이션.md) `curation.json`(내용유형·글자포함·용도)** 이다 — 두 파일에 기록이 있는 이미지는 **그 기록으로 판단**한다([5단계 §7](일-5단계-디자인시스템.md)의 "시각 분석은 4단계 결과 재사용 · 재분석 금지"와 같은 원칙. 2단계에서 전수 OCR, 4단계에서 한 장씩 비전 정독을 이미 했다). **직접 열어야 하는 것은 다음 셋뿐**: ① 두 파일에 기록이 없는 이미지 ② `ocr.json`에 `needsOcr:true`인데 전사가 비어 있는 이미지 ③ 세로 긴 패널의 **크롭·잘림을 눈으로 확인**해야 할 때. ⚠️ 기록이 없어서 못 본 것을 "안 봤으니 뺀다"로 처리하는 건 여전히 사유 불인정 — 그건 열어서 본다.
> 2. **분류표 작성·갱신 — 손으로 쓰지 말 것**: `npm run images:report`([5단계 §물질화 스크립트](일-5단계-디자인시스템.md))로 **[docs/이미지-배치표.md](이미지-배치표.md)를 자동 생성**한다. 파일·카테고리·**배치 페이지·사용 여부는 src 참조 스캔으로 자동**이고, **사람이 채우는 건 미사용 행의 `사유` 한 줄뿐**이다(재생성해도 그 사유는 승계된다). 페이지를 고칠 때마다 다시 돌리면 표가 항상 실제 코드와 일치한다. **콘텐츠·정보가 있는 검증 자산(공식 브로슈어 보드·도면·지도·시설 컷)은 사용이 default**, 제외는 예외(사유 필수). "안 봤으니 뺀다"·"near-dup일 것 같아서 뺀다"는 **사유로 불인정**.
> 3. **완료조건 증명**: 각 페이지 완료 시 아래 [완료 조건](#완료-조건-사람용-요약)을 **항목별 ✅로 증명**(특히 "콘텐츠 이미지 전부 배치 / 1~2장 방치 0"). 미충족이면 미완료.
> ⚠️ **필러 금지(억지 배치 = 어뷰징)**: "이미지 최대 활용"은 **콘텐츠/정보가 있는 자산** 한정이다. **정보 가치 없는 장식·배경(추상 구름/색면 밴드·빈 배경·단순 텍스처 등)은 채우려고 억지로 넣지 말고 `미사용(사유: 장식·정보 없음)`으로 분류**한다. 즉 "검증 자산 default 사용"과 "필러 금지"를 함께 지킨다 — **정보 있으면 쓰고, 장식뿐이면 뺀다.** (채우기용 이미지 = '채우기' 어뷰징과 동일.)
> ※ **near-duplicate 금지 = "같은 이미지를 두 페이지에 중복 게재" 금지**일 뿐, **한 페이지 안에서 콘텐츠 이미지를 적게 쓰는 핑계가 아니다.** 텍스트 워딩의 near-dup만 피하면, 검증 콘텐츠 이미지는 최대한 다 쓴다.

> 분양원본은 대개 **콘텐츠가 이미지(CG)에 임베드**돼 있고 추출 텍스트는 면책 문구뿐이다. 따라서 서브페이지는 "이미지를 크게·많이 보여주고, 검증된 fact로 H2를 채우는" 구조가 기본이다. 빈약하게 만들지 말 것.

- **현장명 본문 밀도 — 대명사 환원**(정본 = [14단계 §브랜드 토큰 본문 밀도](일-14단계-SEO-GEO.md)): 서브 본문도 "본 단지·본 현장·이 단지" 대명사가 브랜드를 먹지 않게 **현장명으로 환원**한다. 진단선 **250자당 1회**(400자당 1회보다 묽으면 보강). ⚠️ **서브는 대명사 환원까지가 원칙** — 횟수를 채우려 문장을 지어 넣지 않는다(메인의 요약 블록 추가는 서브에 적용하지 않음, 서브끼리 near-duplicate 유발). **TITLE·H1·H2는 각 페이지 정본 그대로**(브랜드 접두어는 H1·title이 이미 받침 — 헤딩으로 밀도를 올리지 말 것). alt·JSON-LD에만 현장명이 몰린 상태도 동일하게 교정 대상.
- **큐레이션 이미지 최대 활용** — 해당 섹션(category)으로 keep된 이미지는 **원칙적으로 전부 배치**(풀와이드 쇼케이스·갤러리·카드·밴드로 소진). 1~2장만 쓰고 방치 금지. 미사용분은 완료 시 그 사유를 명시.
- **세로 인포그래픽 패널 = 풀와이드 무크롭** — 글자/도면이 박힌 세로 긴 이미지(조경·커뮤니티·평면도·입지안내도 등, 가로세로비 < 1)는 `next/image`의 `width`/`height` intrinsic + `h-auto w-full`로 **자르지 않고** 크게 노출. `fill`+`object-cover` 크롭 금지(글자 잘림). 가로비 이미지만 aspectRatio 컨테이너+object-cover 허용.
  - ⚠️ **무크롭 이미지 = 시각 전달용일 뿐, 텍스트 충족이 아니다.** 그 이미지 안의 글자 fact(면적표·스펙·시설명·수치)는 검색·AI가 못 읽으므로 **alt로도 불충분 → 본문 HTML 텍스트(표·목록·문단)로 반드시 별도 전사**([3단계 ⑦ 전사 대장](일-3단계-검증보강.md) 처분=전사/병기 기준). "이미지가 크니 텍스트는 얇아도 된다"는 판단 = thin content 원인, 금지.
- **H2 섹션 다수 + 하단 About** — 섹션을 충분히 쌓고(각 SectionHeading) 페이지 끝에 `AboutThisPage`(SEO 자연어 본문). 분량은 [6단계 §F](일-6단계-전역규칙.md) 기준.
- **이미지 속 텍스트는 OCR 검증값만** — 시설명·정원/광장명·동별 층수·룸 구성 등 이미지에 박힌 정보는 `extraction/ocr.json` 등 1차 검증값만 사용. **없는 명칭 창작 절대 금지**(예: 임의 정원명). 확정 fact는 [content.ts 단일소스](일-5단계-디자인시스템.md).
- **권장 섹션 순서(이미지 우선)** — 인트로 리드(1~2문장) → 대표 비주얼(풀와이드) → 핵심 fact 섹션 다수(H2 + 이미지/인포그래픽 동반, 원본 사이트의 서브구조 순서를 따름) → 하단 `AboutThisPage`.
- **섹션 영역 적합성 ≠ 이미지 축소** — 각 페이지는 **그 페이지 주제에 맞는 이미지를 전부 활용**(갤러리·풀와이드·범례). "대표 1컷만 남기고 줄이기" 금지. 단, **주제와 무관한 섹션을 끼워넣지 말 것**(적합성은 지키되 이미지 수는 최대).

### 페이지별 섹션 → 콘텐츠 매핑 (영역 적합성 — 이대로 배치)

> ⚠️ **단지 외관 CG(조감도·투시도)는 사업개요·단지안내가 나눠 갖는다 — 같은 이미지를 두 페이지에 중복 게재하지 말 것(near-duplicate=어뷰징).** 대표 **조감(항공)**은 사업개요 오프닝 쇼케이스, **투시도(보행자 시점)**는 단지안내. 분할해 **각 이미지는 한 페이지에만**(반복 실수 지점).

| 페이지 | 들어가는 콘텐츠 | 들어가면 안 되는 것 |
|---|---|---|
| **사업개요 `/overview`** | **대표 단지 조감(항공) 2~3컷 쇼케이스**·사업 개요 LineSpec(표)·건축 규모·사업주체 | 투시도 갤러리(→단지안내), 조경·커뮤니티·배치도, 단지안내와 **동일 이미지 중복**, ★**구내용 이동통신설비(구내중계설비) 안내 — 내용·이미지 모두 금지** |
| **입지환경 `/location`** | 입지 지도·교통·반도체클러스터·공원/하천·도시개발·생활인프라·입지안내도 (입지 강점 상세는 **여기만**) | 단지 조감·평면도, 길찾기 버튼(`MapLinks` 미사용 — 위치는 입지 지도·안내도 이미지로) |
| **프리미엄 `/premium`** | **단지/브랜드 차별화**(브랜드·국민평형·특화설계·커뮤니티 요약·미래가치). 입지·단지는 **요약 1~2줄+링크만** | 평면도·배치도, **입지/단지 상세 워딩 복제(→입지환경·단지안내, near-duplicate 금지)** |
| **단지안내 `/complex`** | **단지 투시도**·단지설계·단지조경·그리너리 라운지(커뮤니티)·단지배치도·동호배치도 | 평면 상세(→평면도), 분양가(→분양안내) |
| **평면도 `/floorplan`** | 주택형 표·평면도·평면 구성(룸)·옵션 | 단지 배치/조경 본문, **견본주택 인테리어 갤러리(→모델하우스, 텍스트 링크만)** |

> ⚠️ **프리미엄 ≠ 입지환경 복제**: 프리미엄은 "이 단지를 왜 사는가"(브랜드·상품·종합 요약), 입지환경은 "입지 fact 상세". 같은 셀링포인트를 두 페이지에 같은 워딩으로 펼치면 near-duplicate(어뷰징). 프리미엄은 요약+링크, 상세는 해당 페이지에 1곳만.
> ⚠️ **인테리어/견본주택 컷은 모델하우스 전용**(12단계). 평면도 페이지는 평면·면적·옵션까지, 인테리어는 텍스트 링크로만(이미지 중복 게재 금지).
> 🚫 **사업개요에 「구내용 이동통신설비 안내」 넣지 말 것(내용·이미지·표·CG 전부)** — 입주자모집공고 PDF에 있어도 **웹사이트로 옮기지 않는다**. 이동통신 구내중계설비 설치·비용부담·통신사 협의 등은 방문자의 **구매 판단과 무관한 서류상 고지**이고, 원문은 모집공고 PDF가 이미 담당한다. 관련 이미지가 큐레이션에 keep돼 있어도 **4단계 [분류표](이미지-배치표.md)에 "미사용 — 사업개요 제외 규칙"으로 기록하고 배치하지 않는다**(이미지 최대 활용 원칙의 예외 = 규칙 위반 아님). 옮겨 적는 작업 자체가 시간낭비이며 thin/무의미 섹션만 늘린다.

- 이미지 카테고리(`public/images/<cat>`)는 **표시 위치**와 다를 수 있다 — 원본 파일명 카테고리가 아니라 **콘텐츠 주제**로 배치 페이지를 정한다(예: `images/overview/*` 조감컷은 파일명이 overview여도 "단지 조감"이므로 `/complex`에 배치).

## 사업개요 `/overview` (모티프 `circle`)

- **TITLE** `{현장명} 사업개요` (`/news`와 "공급정보" 키워드 중복돼 꼬리 삭제) · **DESC**(≤80) `{현장명} 사업개요. {위치} {규모} {N}세대, {전용면적}, 사업주체까지 한눈에 확인하세요.`
- **H1** `{현장명} 사업개요` · **H2**(H1 중복 제거·fact 키워드) 브랜드 스토리 · 건축 설계({설계사}) · 사업 개요 — {N}세대 · {전용면적} · {규모}.
- 위치·대지·건축규모·공급규모·사업주체 등 fact = **`LineSpec` 표**(개별 H2 X):
  ```
  01 / 단지명          {현장명}
  02 / 위치            {주소}
  03 / 건축규모        지하 N층 ~ 지상 N층 (예시)
  04 / 총 세대수       {N세대 (일반분양 N세대)}
  05 / 전용면적        {59~155㎡, N개 주택형}
  06 / 입주 예정       {YYYY년 M월}
  ```
  - `LineSpec`: 좌 브론즈 인덱스(`font-accent` 15px) + `text-muted` 라벨 15px + 우 값. 값(dd) **`text-ink` 17~18px·weight 500**, 자간 안 벌림, 행 사이 `border-line`, `py-5`.
- **About**(eyebrow `About This Page`) `사업개요 한눈에 보기` 자연어 2~3문단(확정 fact만): 위치·규모 / 주택형·설계 / 사업주체·안내(분양가·일정은 입주자모집공고 기준 추후, 상담 {전화}). 권장 800~1,500자.

## 내부링크 시스템 (심플 통일 — SEO·AI 유입 최적) — 11·12·13 공통 정본

> **전제: 전역 헤더 nav + 다크 푸터 nav가 9개 페이지를 모두 상호연결**한다(크롤·접근·orphan 0 이미 보장). 그러므로 서브에 **"관련 페이지" 카드 블록·링크 매트릭스를 따로 만들지 않는다**(= nav 중복·사이트와이드 보일러플레이트 링크 → 가중치 희석). **과거 카드 매트릭스(`RelatedPages`)·인바운드 카운팅 방식은 폐기.**

### 구조 — 4층, 그 이상 만들지 않는다
1. **전역 nav + 푸터** = 전체 상호연결·크롤 동선(이미 존재). **서브에서 재현 금지.**
2. **Breadcrumb JSON-LD** = 계층 신호. 전 서브 `홈 / {제목}`(PageHero `path` 자동). 중복 생성 금지.
3. **본문 맥락 링크 = 페이지당 0~2개**(강제 아님 — 그 문장에서 **진짜 자연스러운 곳에만** 인라인). **같은 URL 1회**, 서술형 앵커("84A 평면도"·"분양가·일정"·"견본주택 위치"). **한 문장에 몰기·"여기 클릭"·동일 앵커 반복 0.** 방향은 **퍼널 앞으로**(입지→평면도→분양→모델하우스) 또는 **혼동 방지 1개**(예: 입지=현장 vs 모델하우스=견본주택).
4. **하단 전환 CTA = 관심고객 등록 버튼 1개**(`PageOutro` → `/modelhouse#reservation`). 그 외 버튼·중복 CTA 금지. ⚠️ **CTA 밴드 배경 = 밝은 톤(`bg-background`/`bg-surface`)** — 바로 아래 다크 푸터(`bg-ink`)와 **같은 색 인접 금지**(다크 풀폭 밴드로 깔면 푸터로 오인 → 밴드는 밝게, 버튼만 어둡게). 배경 규정 = [8단계 §1 버튼](일-8단계-공통컴포넌트.md).

### About("한눈에 보기") = 링크 0, AI 인용 최적 요약 — 11·12·13 공통 정본
- ★**제목 형식 = eyebrow 영문 `About This Page` + H2 `{주제} 한눈에 보기`**(`SectionHeading as="h2" en="About This Page"`). ⚠️ **About H2엔 현장명 접두어 넣지 말 것** — 현장명은 H1·title·OG·breadcrumb·본문 첫 문단이 이미 받침. 7개 서브 About에 현장명을 또 박으면 **브랜드 H2 반복=키워드 스터핑(어뷰징)** → 주제어만 쓴다. (eyebrow는 장식 영문이라 SEO 가중치·어뷰징 무관, 통일성용.)
- **링크 0**(순수 요약). **한 문장 = 한 fact**(역명·시설 등 entity + 세대수·면적·층수·연도 등 수치 명시)로 **자기완결**, **첫 문단만 `{현장명}…`로 시작**해 AI 인용 fact를 브랜드와 연결. → 네이버 AI·검색 인용에 그대로 쓰이는 단락.

### AI 유입(GEO) 우선 원칙
- **AI 인용은 링크 수가 아니라 fact 밀도·자기완결성으로 결정**된다. 내부 동선은 nav·breadcrumb로 충분하니, 본문·About는 **링크 최소·fact 최대**로 간다.
- 링크가 문장을 끊지 않게 — 인용 단위(문장)는 깨끗하게 유지.
