## 1. 버튼 (UI §3.2)

| 변형 | 스타일 |
|---|---|
| Primary | 1px 보더(`border-current`/ink) · transparent bg · hover 채워짐/opacity-60 |
| Solid | `bg-ink text-ivory`(모바일 CTA 통바·폼 제출, 풀폭 가능) |
| Text only | underline offset 4px · hover bronze |
| **Circle(어텐션)** | 히어로 단일 핵심 전환 **원형**(`rounded-full` ~128~160px) · 2~3줄 라벨(한글 주+영문 장식) · `motion-safe:animate-ping`+`animate-pulse` 글로우 + hover `scale-105` |

- radius 0(원형 제외), padding `px-5 py-2.5`~`py-4`(터치 48px). 라벨 한글 주+영문/숫자 보조, 자간 0.05em 이하. 브론즈 버튼 텍스트 14px 미만 금지.
- 이미지 위 원형 CTA = 따뜻한 야경엔 샴페인/웜톤 원+잉크 글자(흰색=떠 보임, 다크=묻힘), 글로우 브론즈, `motion-safe` 한정.
- **서브 하단 전환 CTA(`PageOutro`) 밴드 배경 = 푸터와 다른 밝은 톤 필수**: 서브 하단 관심고객등록 CTA 밴드는 **`bg-background`(아이보리) 또는 `bg-surface`(흰)** 섹션 위에 올리고, **버튼만** Solid(`bg-ink`)·Primary(아웃라인)·브론즈 액센트로 처리한다. ⚠️ **CTA 밴드 전체를 `bg-ink` 다크 풀폭으로 깔지 말 것** — 바로 아래 **다크 푸터(`bg-ink`)와 같은 색이 인접**해 CTA가 푸터처럼 묻힌다(실발생 버그). 푸터 바로 위 블록은 항상 밝은 톤으로 대비를 준다.

## 2. 폼 (UI §3.3)

> **제출 백엔드 연동 = 다음 [9단계](일-9단계-관심고객등록.md)** (Supabase `inquiries` 공유 테이블 + 텔레그램 알림): 8단계는 폼 **UI·필드·동의**까지만 만들고, 제출 연결(`supabase.ts`·`api/contact/route.ts`·`.env.local`)은 9단계가 담당한다. 여기서 백엔드를 중복 구현하지 말 것.

- 입력 = 언더라인 only(`border-b border-line`) 또는 테두리 박스(`border border-line px-4 py-3`) 중 톤에 맞게(폼카드 흰 배경이면 테두리 박스가 또렷).
- **라벨 필드 위 한글 16px 고정**(플레이스홀더 대체 금지 — 플레이스홀더는 예시 입력값만). 입력 17px+ ink.
- 포커스: 보더 색 브론즈 + 언더라인/보더 2px(색만 의존 X).
- **에러 한글 우선**(`연락처를 올바르게 입력해 주세요`, `text-ink`+굵기 500). 색은 ink 계열, 아이콘/굵기로 구분.
- 필드 간 세로 간격 `gap-7`+. 제출 버튼 풀폭 `bg-ink`.
- **개인정보 동의**: 수집항목·이용목적·보유기간 **테두리 박스로 분리** + 동의 체크박스 + 처리방침(`/privacy`) 링크(개인정보보호법 필수).
- **관심고객등록 폼 정본 필드**: `성함`·`연락처`·`연락 가능한 시간대`(라디오: 오전9–12/오후12–15/오후15–18/저녁18 이후/아무때나)·동의 — 별도 페이지 없이 메인 하단 + 모델하우스.
- **연락처 자동 하이픈(가독성 필수)**: 입력 즉시 숫자만 추출해 `-`를 자동 삽입한다(`010-1234-5678`). `onChange`에서 `formatPhone()` 적용 — 02(서울) 2자리 국번, 그 외 3자리 국번, 11자리=`3-4-4`/10자리=`3-3-4`. `inputMode="numeric"`(모바일 숫자패드), `maxLength={13}`. 검증 정규식(`/^0\d{1,2}[-\s]?\d{3,4}[-\s]?\d{4}$/`)은 하이픈 포함 값을 그대로 통과.
- **선택 헤더 prop**: `eyebrow`(영문 라벨)·`title`·`note`로 폼 상단 제목/안내 표시(예: `Reservation Form` / `방문예약 신청` / `담당자가 확인 후 연락드려…`). 메인·모델하우스에서 재사용(좌 정보 ↔ 우 폼 영문 eyebrow 대칭).
- **전환 추적(GA4 — `site.ts` `gaId` 설정 시만 활성)**: `src/lib/analytics.ts`의 `track(event, params)` 헬퍼 경유 — 폼 제출 **성공 시**(api 200 응답 후) `form_submit_success`(폼 위치 파라미터), `tel:` 링크 클릭 시 `tel_click`(헤더/히어로/콜바/푸터 위치 파라미터). GA 스크립트는 `@next/third-parties` `<GoogleAnalytics>`를 layout에 **gaId 있을 때만 조건부** 삽입(afterInteractive — LCP 영향 최소), gaId 빈값 = no-op(스크립트 0바이트·에러 0). ⚠️ **폼 입력값(성함·연락처 등 개인정보)을 이벤트 파라미터로 전송 절대 금지**(개인정보보호법) — 이벤트명·위치 파라미터만. 검증 = [16단계 G16-ANALYTICS](일-16단계-배포점검.md).

## 3. 섹션 헤딩 (`SectionHeading`, UI §3.4)

- 브론즈 번호(`font-accent` italic 15px, tracking-widest) + `font-serif` bold 헤드(26px → `sm:34px`, `text-ink`).
- `no` prop 선택 — 번호 없는 헤딩도 허용.

## 4. 라인 디스플레이 (`LineSpec`, UI §3.5)

- `border-t/b border-line`, 각 행 `py-5`. dt = 브론즈 번호(15px) + `text-muted` 라벨(15px), dd = `text-ink` 17~18px **medium**.
- 사업개요·공급정보 등 "라벨/값" 표는 모두 이 컴포넌트로 통일.

## 5. 카드 / 이미지 (UI §3.6)

- 카드 최소화. 사용 시 transparent bg · `border-line` 1px · radius 0 · hover 시 보더 ink로 진해짐(transform 없음). 제목 18px+ / 본문 16px+.
- hover 미세 scale(1.02)+ease-out. 이미지는 `<Link>`로 감싸 **클릭 가능 + 호버 줌**(`group-hover:scale-[1.02]`).
- **이미지 잘림 방지(중요)**: 비율 제각각(가로 조감~2.0, 세로 외관~0.7, 정사각 지도). 고정 `aspect`(예 4/3)+`object-cover`로 묶으면 전부 잘림 → 둘 중 하나:
  - 컨테이너 비율을 **각 이미지 실제 비율**(`style={{aspectRatio:w/h}}`)에 맞춤 → `object-cover`여도 잘림 0.
  - 튀는 컷(세로 외관)은 같은 톤 가로 이미지로 교체.
  - `next/image`는 width/height(또는 비율) 명시(CLS 방지). webp 우선.
  - **`sizes` 명시(전송량·LCP)**: 풀와이드 = `sizes="100vw"`, 2단 그리드 = `sizes="(min-width:1024px) 50vw, 100vw"` 등 **실제 렌더 폭**을 알려준다. 미지정 시 next/image가 뷰포트 100% 가정으로 과대 해상도를 전송해 LCP·전송량 손해(특히 무크롭 세로 인포그래픽·갤러리 그리드에서 체감 큼).
- **캡션은 이미지 아래 단색 배경에 16px+.**

## 6. 섹션 매거진 블록 (`MagBlock`, UI §3.7)

- 메인·서브 "이미지+내용" 섹션 정본. props `{ no, en, title, image, alt, ratio, href, linkLabel, reverse, bg, children, placeholder }`.
- 2단 그리드(`lg:grid-cols-2 items-center`), `reverse`로 이미지 좌/우 교차. 내용 = eyebrow(번호+영문) → H2(serif) → `children`(fact 문단/리스트/`LineSpec`) → 자연어 링크.
- 이미지 컨테이너 `style={{aspectRatio:ratio}}`(=실제 w/h). ⚠️ **이미지엔 링크·hover 줌 없음 — 이동은 `linkLabel`로만**([10단계 §섹션 매거진 블록] 정본). `<Link>` 래핑·`group-hover:scale` 금지(과거 사양 폐기).
- `bg`는 섹션 교차색(`bg-surface`/`bg-background`)을 호출부에서 번갈아 주입.
- ⚠️ 같은 섹션을 "상단 카드 네비 + 하단 텍스트"로 **이중 배치 금지** — MagBlock 하나로 통합(중복 방지).
- ★**`placeholder` prop (사용자 직접 첨부 슬롯 전용 — 10단계 정본)**: `placeholder`가 참이면 이미지 자리에 **빈 중립 박스**를 렌더한다 — `border border-dashed border-line` + `bg-background`, 중앙 `text-muted` 15~16px 한 줄 **"이미지 준비 중 · 사용자 첨부 예정"**, 링크·아이콘·장식·샘플이미지 0. 박스 비율은 호출부 `ratio`(미지정 시 `aspect-[4/3]`)로 옆 텍스트와 높이 균형을 맞춘다.
  - `placeholder`일 때 **`<Image>`를 렌더하지 않는다** — 빈 `src`·1×1 더미·외부 스톡 이미지 대체 금지(404·CLS·G16 위반). `alt`도 요구하지 않는다(이미지가 없으므로).
  - **적용 대상 = 메인의 평면도·분양안내·모델하우스 3슬롯**(10단계 §섹션 매거진 블록). 사용자 이미지 수령 시 `placeholder` 제거 + `image`/`ratio`/`alt` 연결로 **한 번에 교체** — ⚠️ `placeholder`와 `image`를 **동시에 주지 말 것**(교체 누락이 조용히 묻힌다).
  - ⚠️ 박스 문구는 **게이트 판정 문자열**이다 — `[G10-IMG]`가 메인 HTML에서 **`사용자 첨부 예정`을 박스 1개당 1회로 세어** 남은 슬롯 수를 판정한다(첨부 완료 슬롯은 이미지 렌더로 판정). 문구를 바꾸거나 박스당 2회 이상 쓰면 오판정 → RED.

## 7. 위치/주소 안내 (길찾기 버튼 미사용)

- ⚠️ **`MapLinks`(네이버·카카오·구글 길찾기 3버튼) 미사용** — 외부 지도앱으로의 이탈은 전환(방문예약 폼)에서 벗어나게 하고 SEO·AI 유입 기여가 0이라 **전 페이지에서 제외**.
- 위치는 **주소·전화 텍스트 + 위치안내 표 + 입지 지도/안내도 이미지**로 안내하고, 주소·전화는 모델하우스 `LocalBusiness`/`RealEstateAgent` **JSON-LD**([12단계](일-12단계-서브-분양-모델하우스.md))로 구조화 노출(검색·AI가 읽는 건 길찾기 버튼이 아니라 이 구조화 데이터).

## 8. 개인정보처리방침 (`/privacy`)

- 관심고객등록 폼의 **개인정보 동의 대상 페이지**(§2 폼 동의 박스 → `/privacy` 링크). 라우트 골격은 7단계, **본문은 여기 규정**(빈 골격 방치 금지 — 개인정보보호법상 폼 운영 요건).
- **개인 운영이면 간소화** — 표/리스트로 핵심 항목만: 수집 항목(성함·연락처·연락 가능 시간대) / 이용 목적(분양 상담·방문예약 안내) / 보유 기간(분양 종료·동의 철회 시 파기) / 제3자 제공(미제공, 법령 예외) / 정보주체 권리(열람·정정·삭제·동의 철회) / 동의 거부(가능, 거부 시 안내 제한) / 문의처(대표문의 `{전화}`) / **시행일(`LEGAL.lastUpdated`)**.
- **기업 운영이면 추가**: 처리 위탁·파기 절차·안전성 확보 조치·개인정보 보호책임자(성명·연락처). ⚠️ 보호책임자 등 **미확보 정보는 창작 금지**(확보 시 추가).
- **추적 도구 도입 시 고지(1줄)**: GA4 등 행태정보 수집 도구를 심은 현장은 처리방침에 "서비스 이용 통계·개선을 위해 Google Analytics를 사용하며, 개인 식별 정보는 수집하지 않습니다" 1줄 추가(gaId 미설정 현장은 생략).

## 9. 출처 주석 (`SourceNote`)

- **근거 매체를 본문 문장에 섞지 않고 모아 두는 자리**([6단계](일-6단계-전역규칙.md) §C 출처 자백). 섹션 또는 페이지 본문 **맨 아래 1개**. props `{ items }` — `{ media, date, url? }` 배열.
- 형식 `※ 출처: {매체}({YYYY.MM.DD})` · 원문 URL 있으면 매체명에 링크(`target="_blank" rel="noopener"`). 여러 건은 `·`로 나열(문단으로 풀어쓰지 말 것).
- 스타일: 15~16px `text-muted`, 위에 `border-line` hairline 1px + `pt-4`로 본문과 분리. 장식 없음.
- **다는 대상 = 언론에서 온 서사·호재·시장맥락뿐** — [3단계](일-3단계-검증보강.md) ⑦ 전사 대장의 `※ 표기=필요` 행 ↔ ⑧ 보도 대장과 1:1. ⚠️ **1차 문서(입주자모집공고·건축물대장·지자체 고시)에서 온 확정 fact엔 달지 않는다** — 그건 시점 단서(`{공고일} 모집공고 기준`)와 공고문 PDF 링크로 이미 근거가 선다([14단계](일-14단계-SEO-GEO.md) E-E-A-T). **공고문 PDF 링크를 빼라는 뜻이 아니다.**
- 쓰는 곳(이름·형식 통일): `/location` 개발호재([11단계](일-11단계-서브-단지정보.md)) · `/news/[slug]` 출처 주석([13단계](일-13단계-서브-소식-FAQ.md)) · 분양소식 `sourceNote`([15단계](일-15단계-운영-분양소식.md)). **출처 0건인 페이지엔 렌더하지 않는다**(빈 ※ 금지).
