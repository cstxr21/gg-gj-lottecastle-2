# 0. 시작하기 — 이 폴더를 처음 여는 AI가 먼저 읽는 1장

이 폴더는 **일반분양(선착순 단계) 현장 홈페이지를 만드는 16단계 작업 지시서**다.
각 단계 md는 자기완결이라 그 단계에 필요한 건 그 파일 안에 다 있다. 이 문서는 **순서·현재 위치·절대 규칙**만 담는다.

**작업 방식**: 각 단계 md의 ` ``` ` 프롬프트 블록이 실행 대상이고, 그 밖(참고·완료조건 요약)은 사람용이다.
**시작 전 1회**: [16단계](일-16단계-배포점검.md) §마스터 검증 스크립트의 코드블록을 `scripts/verify.mjs`로 저장한다. 이게 없으면 어느 단계도 완료 판정을 못 한다. 1단계에서 `package.json` scripts에 `typecheck`·`verify`·`verify:build` 3개를 넣는 것도 같이 끝낸다 — 이후 모든 단계가 이 이름으로 판정한다.

## 절대 규칙 (어기면 되돌리기 어려움)

1. **수치 창작 0.** 확인 안 된 값은 지어내지 않는다. 미확정은 **"입주자모집공고 시점 기준 추후 안내"** — 값 자리에 짧게, 문단으로 변명하지 말 것.
2. **사이트는 정보를 주는 주체다.** 출처 자백("보도에 따르면·알려졌다")·편집 변명("참고용으로·본 페이지는")·자료 사정("확인되지 않아")을 본문에 쓰지 않는다. 출처는 **하단 ※ 주석**으로. → [6단계](일-6단계-전역규칙.md) §C
3. **HTML title은 READ-ONLY.** 10~13단계에서 정해진 title은 이후 어떤 이유로도 바꾸지 않는다(제안·평가도 금지). → [14단계](일-14단계-SEO-GEO.md)
4. **표시광고법**: "최저가/확정/완판/직결" 단정·비교 금지, 광고심의필·시행/시공(/신탁) 3주체 푸터 유지, 수치엔 `{공고일} 입주자모집공고 기준` 시점 단서.
5. **미분양 인식 주는 표현 금지**: 지나간 청약 일정 나열·"종료" 제목 금지 → "선착순 분양 중"으로 능동 표기.
6. **9단계 실값(Supabase·텔레그램 키)은 깃 커밋 금지.** 현장 레포에 docs 복붙 시 [9단계](일-9단계-관심고객등록.md)는 제외하거나 키 줄을 지운다.
7. **현장 fact를 범용 md에 쓰지 않는다.** 진행현황·현장 수치·파일명은 `검증리포트.md`·`이미지-배치표.md`·`reports/*.json`에만. 범용 md를 오염시키면 다음 현장 복붙이 망가진다.

## ⚠️ 순서 함정 (이것 때문에 되돌아간다)

- **키워드 리서치는 3단계 직후에 한다 — AI가 자동 수행(`scripts/keywords.mjs`, 네이버 자동완성 스윕)하고 게이트 `G3-KEYWORD`(blocker)가 시점을 강제한다.** [14단계](일-14단계-SEO-GEO.md)에 적혀 있지만 실행 시점은 **3단계 직후·5단계 시작 전**이다. 10~13단계 title이 이 결과로 확정되고 title은 READ-ONLY라, 14단계에서 처음 하면 못 되돌린다.
- **15단계는 번호와 시간 순서가 다르다.** 실제 진행은 **14단계 → 15-A(지역 롱테일 2~4편) → 16단계(배포점검) → 15-B(현장 사건 뉴스, 사건 발생 시에만)** 다. 빈 `/news`로 배포하지 않으려고 15-A만 16단계 앞에 오고, 나머지는 배포 후 사건이 터졌을 때만 쓴다(15단계 §0).
- **3단계와 4단계는 병렬.** 둘 다 2단계 산출물만 소비한다. 순서대로 기다리지 말 것.
- **2단계 OCR이 부실하면 그 뒤가 다 얇아진다.** 분양 원본은 콘텐츠가 CG 이미지에 박혀 있다 — 인포그래픽 패널 OCR 누락 0을 2단계에서 확인하고 넘어간다.
- **중간 단계에서 `npm run verify`를 필터 없이 돌리지 말 것.** 아직 안 만든 단계가 RED로 나와 시간만 버린다. → `npm run verify -- --stage=N`
- **매 단계 `next build`를 돌리지 말 것 — 시간을 가장 많이 잡아먹는 지점이다.** `npm run verify`는 빌드하지 않고(빌드가 필요한 게이트만 `⏭ 미판정`으로 남긴다), 문법·타입은 `npm run typecheck`로 본다. 빌드 포함 판정은 **단계 마감 때 1회** `npm run verify:build -- --stage=N`, 배포 직전에 `npm run verify:build`. `.next`가 소스보다 오래되면 빌드 게이트는 자동으로 ⏭ 되므로 옛 빌드로 통과할 일은 없다.

## 현재 어디까지 됐는지 판별

프로젝트 폴더에 **아래가 있으면 그 단계는 끝난 것**으로 보고, 없는 첫 줄부터 시작한다.

| 있으면 완료 | 단계 |
|---|---|
| `package.json` + `src/lib`·`src/components` 폴더 | 1 |
| `<SAVE_PATH>/ocr.json`·`manifest.json` | 2 |
| `factcheck.json`·`검증리포트.md` | 3 |
| `curation.json`·`curated/` | 4 |
| `src/lib/content.ts`·`site.ts` + `globals.css` 토큰 | 5 |
| `src/components/Header.tsx`·`Footer.tsx` | 7 |
| `src/components/InterestForm.tsx` + `/privacy` 본문 | 8 |
| `src/app/api/contact/route.ts` | 9 |
| 각 라우트 `page.tsx` | 10~13 |
| `sitemap.ts`·`robots`·페이지 JSON-LD | 14 |
| `/news` 발행 글 | 15 |

확실치 않으면 `npm run verify -- --stage=N`을 낮은 N부터 돌려 첫 RED가 나오는 단계가 현재 위치다.

## 게이트

- 각 단계 md 맨 아래 `## 완료조건 (기계 판정)`의 `[Gxx-*]`가 그 단계의 합격 기준이다.
- 실행(작업 중·수 초): `npm run verify -- --stage=N` — 빌드하지 않는다. `.next`가 필요한 게이트는 `⏭ 미판정`으로 찍힌다.
- 실행(단계 마감·배포): `npm run verify:build -- --stage=N` / 배포는 필터 없이 `npm run verify:build` — **전부 GREEN 전엔 "완료"라고 말하지 않는다.**
- 선언 형식: `[Gxx-KEY] 설명 | auto|manual | blocker|권고` — 16단계 `scripts/verify.mjs`가 이 줄을 파싱한다. **blocker**=하나라도 FAIL이면 그 단계 미완료·배포 불가, **권고**=출력에 남지만 진행을 막지 않는다(다음 배포 개선).
- `auto` = 스크립트가 빌드결과·`src`·`public`을 읽어 판정. `manual` = `reports/manual-evidence.json`에 증거(수치·경로·요약)를 채워야 PASS.
- md에 `[Gxx-*]`를 새로 선언하면 **16단계 `CHECKS`에도 검사를 반드시 추가**한다(1:1 계약 — 한쪽만 있으면 RED 또는 경고).

## 현장 산출물 vs 범용 문서

- **범용(이 폴더 md 16개 + 이 문서)** = 다음 현장에 그대로 복붙하는 것. 현장 이름·수치·진행현황을 적지 않는다.
- **현장 산출물** = `검증리포트.md`·`이미지-배치표.md`·`reports/*.json`. 현장 고유 값은 전부 여기와 `content.ts`에.
